# Review of the LLM-generated test suite

This document records what the LLM-generated tests did when they were actually run,
where they were wrong, how each problem was found and corrected, and what human
review still has to do. The source code (`*.cpp`, `*.h`) was not changed; only tests,
the test runners, and the coverage tooling were.

Two suites are compared throughout:

- **As committed** (`09581cb`): the suite the LLM produced, plus the coverage tooling.
- **Now**: after human review (this change).

## 4. Hallucinations and inaccuracies in the LLM-generated tests

Each entry gives: what was generated, why it was wrong, how it was found, how it was
corrected, and whether the suite improved.

**H1. Three tests encoded defects as correct behaviour.**
- *Generated*: `config_characterizes_numeric_prefix_accepted` (expects `"Time Limit:20abc"`
  to give 20), `config_characterizes_crlf_keeps_carriage_return_in_region_name`
  (expects `"region1.csv\r"`), `region_characterizes_trailing_comma_is_dropped`
  (expects `"R,C,"` to give 2 cells).
- *Why wrong*: the tests were written by reading the program's current output, not the
  specification. Trailing `\r` in a CRLF file and a dropped trailing empty CSV field are
  bugs, not behaviour to keep. "20abc" being accepted is a defect (the value is not a
  number).
- *How found*: reviewing each assertion against the source and RFC 4180 for CSV. The
  names said "characterizes", which is a warning sign in itself.
- *Correction*: converted to `XFAIL_TEST` with the correct expectation and a reason
  string. The harness reports them as known defects, and reports `XPASS` (a failure) if
  one starts passing, so the marker must be removed when the bug is fixed.
- *Impact*: the suite no longer certifies the bugs as correct. Before the change the
  suite was green while these three defects were in place.

**H2. Population print test had a wrong expected string.**
- *Generated*: the expected output was built by string concatenation with the wrong
  spacing and a `substr(0,0)` construction.
- *Why wrong*: the expected string did not match what the printing loop writes.
- *How found*: the test failed on its first run.
- *Correction*: derived the expected string from the loop in `region.cpp`, giving
  `"# T -   \n"`.
- *Impact*: the test now checks real output. It had been a false failure, not a false
  pass, so the suite was not weakened.

**H3. Security suite: a policy decision was counted as a defect.**
- *Generated*: FS-08 expected a region path with `../` to be refused, and counted the
  result as a defect.
- *Why wrong*: the specification does not require path refusal. It is a design choice.
  Treating it as a defect inflates the defect count.
- *Correction*: moved to POL-01 in a POLICY category, reported separately.
- *Impact*: the defect count is now a count of defects.

**H4. A real out-of-bounds bug went undetected by the security suite (IV-12).**
- *Generated*: IV-12 (remove demand at index 20) expected rejection. It passed.
- *Why wrong*: the program reads one past the end of a `std::vector`. That access lands
  in the vector's spare capacity, which AddressSanitizer does not check unless
  `_GLIBCXX_SANITIZE_VECTOR` is defined. The test passed for the wrong reason: the
  harness did not see the error.
- *How found*: a hypothesis from the other out-of-bounds failures (IV-07, IV-11). It
  was verified by rebuilding with `-D_GLIBCXX_SANITIZE_VECTOR`.
- *Result*: `container-overflow` at `main.cpp:241`. IV-12 now fails.
- *Correction*: the flag is now part of the security build and the coverage build.
- *Impact*: 1 more confirmed defect. More important: a PASS from a sanitizer-backed test
  is only as good as the sanitizer's coverage.

**H5. Search-output expectation could never match (IV-19).**
- *Generated*: `^R R $`, anchored to the start of a line.
- *Why wrong*: the program prints the first search row on the same line as the prompt
  text ("...column)R R "), so an anchored pattern can never match.
- *How found*: the first run after tightening the expectation failed; the raw output was
  inspected with `cat -A`.
- *Correction*: expectation changed to `R R $`, and the description narrowed to say it
  checks the top row, which is all the regex verifies.
- *Impact*: the test is correct but weaker than the original wording suggested. This is
  stated in the description.

**H6. The harness crashed on runaway output (IV-08).**
- *Generated*: the runner captured program output into a shell variable.
- *Why wrong*: an infinite-output program (menu loops) filled the variable, and bash
  itself was killed with exit 139. The suite reported a crash of the harness, not a
  result for the program.
- *How found*: the runner exited mid-suite; `bash -x` located the capture.
- *Correction*: output is written to a file under `ulimit -f`, and files over 9 MB are
  classified as "unbounded output".
- *Impact*: the suite runs to completion. IV-04 and IV-18 are reported as findings
  instead of crashing the runner.

**H7. Coverage merge silently skipped every file (merge script, generated).**
- *Generated*: the merge looked for `config.cpp.gcov.json.gz`.
- *Why wrong*: gcov writes `config.gcov.json.gz`. Every file was skipped and the report
  showed 0/0 with no error.
- *How found*: the report had zero totals with no error.
- *Correction*: the filename is corrected. The script now exits non-zero when no data is
  found in any input directory.
- *Impact*: the first run after the fix reproduced earlier numbers.

## 5. Errors introduced during this work (not the LLM's)

These are recorded because the review should cover my own mistakes too.

**E1. Branch coverage was reported with the wrong metric.** I first reported gcov's
"Branches executed", which counts branches only on lines that ran, so it overstated
coverage. It was corrected to "taken at least once". The earlier claim of "100% branch"
for config and region was wrong; the corrected figures are in section 2.

**E2. Commit message says 38 cases; the suite has 35.** The commit `ea7bef1` message was
wrong. It was not amended because it was already pushed. Noted here.

**E3. The first commercial test called the UB path.** My goods/zones test called
`commercial()` with zero workers on the populated path. That path falls off the end of a
non-void function (UB). UBSan reported it and aborted the run. The call was removed, and
the test now checks only defined paths.

**E4. An out-of-bounds index after a failed check.** The trailing-comma test indexed
`g[0][2]` after its own size check had failed. That read was out of bounds, and ASan
aborted the process, which hid every test after it. It now guards the index.

## 6. Human corrections and improvements

Changes made in this review, by file:

- **`tests/test_harness.h`**: added `XFAIL_TEST`. Expected failures are reported as
  `[XFAIL]` and not counted; a passing expected failure is `[XPASS]` and counted as a
  failure. The summary line reports expected failures separately.
- **`tests/test_config_region.cpp`**: converted the three tests in H1 into XFAIL tests with correct
  expectations. Added `config_empty_time_limit_does_not_throw` (an empty `Time Limit:`
  value currently aborts). Guarded the trailing-comma index (E4).
- **`tests/test_goods_zones.cpp`** (new, 27 tests): goods fill and supply order, demand
  boundary indices 0, 19, and out-of-range, `generate_demand` invariants, print line
  counts, demand queue not consumed by printing, and the residential, industrial and
  commercial growth predicates (including the corner-cell and population-threshold
  cases). Corrected the commercial test (E3).
- **`tests/security/run_security_tests.sh`**: vector sanitizer (H4), IV-19 expectation
  (H5), added IV-25 (shell metacharacters in a filename, expected rejection; passes),
  FS-08 moved to POL-01 with a separate count (H3), DP-01 description reworded to say
  it checks the display format, not data exposure.
- **`tests/coverage/run_coverage.sh`**: compiles every `tests/test_*.cpp` (it previously
  left out the goods/zones tests) and builds the CLI with the vector sanitizer.
- **`tests/coverage/merge_gcov.py`**: correct filename (H7); exits non-zero when no data
  is found.

## 7. Remaining gaps

- **`growth.cpp` is at 0%** (105 lines, 168 branches, 8 functions). The security suite
  never advances the simulation, and no unit test calls `growth`. The next test should
  choose "Continue simulation" at the menu and check the two-step stop logic.
- **The `commercial()` and `industrial()` missing-return bugs** are not caught by any
  deterministic test on a normal build. They are reported only when the affected path
  runs under `-fsanitize=return` or UBSan. The fix belongs in the source, which was out
  of scope here.
- **Condition and MC/DC coverage are not measured.** The clang MC/DC profiler was not
  available in this environment.
- **The LLM's predicted coverage was not recorded** (section 3).
- **Known defects are not fixed.** This is a testing assignment, so the source was left
  unchanged. Each known defect has a test that documents it (XFAIL or a security case).
- **The earlier 278 vs 273 line discrepancy** between per-case and aggregate coverage
  was not re-investigated in this pass.

## 8. Reproducing the results

```
make coverage          # builds, runs unit tests and the security suite, writes build/cov/report.txt
```

The security suite can also run alone: `tests/security/run_security_tests.sh`
(optional `FILTER=IV-1` to run a subset).
